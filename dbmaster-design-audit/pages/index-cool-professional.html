DbMaster 设计诊断报告 — 冷专业方向

统一冷暖色温：Slate 冷中性 + 靛蓝品牌色

当前：冷暖冲突

深色 Zinc 灰 + 冷蓝 vs 浅色暖白 + 冷蓝，两种底色的色温相反，品牌蓝在冷暖底上表现不一致。

方向：统一色温

把浅色底也调向 Slate 冷中性（#F8FAFC），与深色深蓝灰同温，使深浅主题共享同一中性家族。

结果：品牌蓝稳定

品牌蓝在冷暖底上都能稳定存在，不再孤立；移除紫色 accent，语义色收敛到蓝 + 成功 / 警告 / 错误。

色彩诊断

从主题一致性、强调色层级、编辑器配色与主题消费入口四个维度梳理问题。

error

深色与浅色像两个产品

暗色模式使用偏暖的 Zinc 灰系背景，而浅色模式使用偏暖的米白；两者共用同一组冷蓝强调色，导致暗色偏冷、浅色偏暖，方向相反。

warning

强调色过多，缺乏主从关系

蓝、紫、绿、黄、红同时作为功能色与装饰色出现，没有明确的主品牌色与辅助状态色区分，界面焦点分散。

warning

SQL 编辑器 Darcula 配色与 Zinc 中性壳脱节

编辑器采用高对比 Darcula 深色主题，而应用外壳为低饱和 Zinc 中性风格，两者在饱和度和色温上均不匹配，形成视觉断层。

info

主题消费入口混乱，多处硬编码

代码中同时出现 Theme.of(context)、AppDesignSystem 与散落的十六进制色值，单一颜色语义无法统一维护。

布局诊断

从信息层级、区域堆叠、Sidebar 动态内容、分栏约束与状态反馈五个角度定位问题。

warning

Header 按钮过多，中间 Spacer 造成大面积真空

Header 左侧聚集数据库、连接、AI 等入口，右侧放置窗口控制，中间以 Spacer 撑开，形成视觉空洞，搜索与全局操作被边缘化。

warning

纵向层叠区域过多

Header / Divider / Workspace / Execution Center / Divider / Status Bar 层层堆叠，水平分割线密集，Workspace 实际可用高度被压缩。

warning

Sidebar 动态插入 MySQL Process Panel，挤压 Tree 空间

连接 MySQL 时 Process Panel 从 Sidebar 底部插入，Tree 区域被向上挤压，用户频繁需要滚动才能访问表节点。

error

Editor/Results 分栏最小高度 50px，结果区可能被压到不可读

分栏控件允许结果区被压至 50px，表格与状态文本几乎无法辨认，容易误操作且影响数据核对。

info

Execution Status Bar 28px + 彩色半透明底，成功态视觉过强

每次执行成功都触发高饱和绿色半透明背景，持续吸引注意力；状态栏高度与色彩权重高于实际工作区，喧宾夺主。

改进路线图

按优先级划分改进项，冷专业方向先做色温统一，再处理布局细节。

高优先级

  • —浅色底改为 Slate 冷中性（#F8FAFC / #F1F5F9），与深色同温
  • —移除紫色 accent（#8b5cf6），把装饰/功能色收敛到品牌蓝
  • —品牌蓝统一主入口：所有 primary action 走 #3574F0 / #5B91F8

中优先级

  • —语义色收敛：success #16a34a、warning 降低饱和、error #dc2626
  • —SQL 编辑器提供冷主题高亮，与 Slate 外壳色温对齐
  • —分割线改 surface 色差，弱化 1px 硬线带来的密集层级

低优先级

  • —折叠 Sidebar 尺寸，最小宽度适配窄屏
  • —Resizer 加宽，提升拖拽手感与可访问性
  • —成功态轻反馈，如短 toast 或微动画
冷专业方向下，色彩叙事先收敛；下一步可进入布局层级重构。
