# 查询工具栏 UX 分析

> 对比基准：DBeaver、TablePlus、DataGrip、Navicat
> 分析日期：2026-06-10

---

## 一、当前布局

```
┌─ 左侧（可滚动）───────────────────────────────────────┬─ 右侧 ──────────┐
│ ▶ ■ │ ✨ │ 💾 │ │ 📑 📜 │ ⇄ │ │ 🧹 │ 📊 │ │ 🔒 │ 🗄️ mydb ▾ │ 🛡️ │ ⊞ │
│ 执行 停止 格式化 保存 书签 历史 方向 导入 计划 事务          连接    数据库  PII  分栏
└────────────────────────────────────────────────────┴────────────────┘
```

- 高度：`toolbarHeight`（36px）
- 左侧：`Expanded` → `SingleChildScrollView` → 按钮 + 分隔线
- 右侧：连接选择器、数据库选择器、PII 按钮、分栏按钮
- `VerticalDivider`（`EditorVerticalDivider`）共 6 处作为分组手段

---

## 二、存在问题

### 🔴 P0 — 严重影响使用

#### 1. 连接/数据库选择器位置不符合认知

| 工具 | 位置 |
|------|------|
| DataGrip | 工具栏**最左侧**（在 Run 按钮之前） |
| DBeaver | 工具栏**左侧**（编辑器上方） |
| TablePlus | 独立顶部栏 |
| **DbMaster** | 工具栏**最右侧** |

**问题**：用户自然扫描从左到右，先看动作按钮再看上下文。放在右边意味着每次确认"我在操作哪个库"眼球需要跳到最后。而且连接/数据库是"上下文信息"，不是"操作"，不应和操作按钮混排在同一行。

#### 2. 分隔线过多，视觉噪音大

当前 6 处 `EditorVerticalDivider` + READ-ONLY badge 边框 + 事务容器边框。对比：

| 工具 | 分隔方式 |
|------|----------|
| DataGrip | 按钮间 `SizedBox(width: 4)` + 颜色区分，**几乎不用竖线** |
| DBeaver | 同组用紧凑排列，组间用 `SizedBox(width: 12)` 留白 |
| VS Code | 组间 8px 间距，无分割线 |
| **DbMaster** | **每组建 1px 竖线** |

视觉上竖线把工具栏割裂成了零散的碎片，而非有机的组。

#### 3. Workspace 模式下工具栏空洞

Workspace 模式有 Tab 的 connection/database 上下文时，`connectionSelector` 和 `databaseSelector` 都返回 `SizedBox.shrink()`，导致右侧 `SizedBox(width: 2)` + `SizedBox(width: 1)` 残余空白。工具栏看起来左右不完整——右边空一块。

### 🟡 P1 — 影响使用效率

#### 4. 无快捷键提示

当前菜单/tooltip 有快捷键名但需要悬停才显示。DataGrip 在按钮**下方**直接标注快捷键。

#### 5. Orientation Toggle 和 Split 按钮重复功能

`_OrientationToggleBtn`（工具栏内）和 Split `PopupMenuButton`（最右侧）都操作编辑器/结果的分栏布局。两个控件分离在不同位置，功能重叠：

| 按钮 | 位置 | 操作 |
|------|------|------|
| ⇄ Orientation Toggle | 工具栏中部 | 切换上下/左右 |
| ⊞ Split Button | 工具栏最右 | 上下/左右/关闭分栏 |

#### 6. 智能导入和格式化的图标重复

`auto_fix_high_outlined` 同时用于 Format SQL 和 Smart Import——用户无法根据图标区分两者。

#### 7. 事务控件视觉权重失衡

事务按钮独占一个带圆角背景 + 边框 + 发光指示器的容器，视觉上比执行/停止按钮（纯图标无背景）更突出。但从频率看，执行按钮远比事务常用。

### 🟢 P2 — 细节打磨

#### 8. READ-ONLY badge 位置

红色 `READ-ONLY` badge 夹在按钮中间，像是一个按钮而不是一个状态指示。应放在面包屑栏或状态栏。

#### 9. 连接/数据库选择器样式与按钮不统一

选择器用 `bgTertiary` 背景的圆角容器 + 文字，按钮用纯图标。两者视觉语言不一致。

#### 10. 没有自适应隐藏

窗口缩小时，左侧按钮可滚动但右侧选择器不可滚动。如果数据库名很长（`maxWidth: 80` 已被截断），信息丧失。

## 三、建议方案

### 方案 A：轻量重组（当天完成）

```
┌─ 左侧 ───────────────────────────────┬─ 右侧 ──────┐
│ [🗄️ conn · db ▾] │ ▶ ■ │ 💾 📑 📜 │ ✨ 🧹 📊 │ 🔒 ⊞ │
│  上下文选择器       操作   文件     工具        分栏    │
└──────────────────────────────────────┴─────────────┘
```

**改动**：
1. 连接/数据库选择器移到最左侧（与 DataGrip/DBeaver 对齐）
2. 去掉 P0-3 中的无效竖线，组间用 `SizedBox(width: 8)` 留白
3. 合并 Orientation Toggle + Split Button 为一个
4. READ-ONLY 移到面包屑栏
5. Workspace 模式隐藏选择器时不留空白

### 方案 B：完全重构（2-3 天）

拆分两层：
- **上下文栏**（24px）：`[连接 ▾] [数据库 ▾]` — 始终可见
- **操作栏**（36px）：纯操作按钮 — 分常用/工具两组

对标 DataGrip 的双层工具栏。
